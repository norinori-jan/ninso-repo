# カルテ機能 設計メモ(データ拡充フェーズ→UIフェーズへの土台)

## 経緯

`人相記入用.docx`(顔の輪郭を大きく描いた手書き記入用シート、正面向きの
顔が2人分)を受け取った。これは実際の鑑定の場で、顔を見ながら額・眉・眼・
鼻・人中・口・耳などの部位ごとに気づいた特徴を手書きでメモしていくための
紙のテンプレートである。

このプロジェクトはここまで「相法の文献をデータベース化する」フェーズ
(`data/*.js` に蓄積された **262項目** のPARTSデータ)を進めてきたが、
今回のリクエストにより、次のフェーズは「そのデータベースを使って**実際の
人物の鑑定記録(カルテ)を作る画面**」の実装に進む。本ドキュメントは、
このカルテ機能の土台(データモデルとUIの方向性)を先にまとめておくもの。
**今回のセッションではコード実装(app.js等)までは行わず、設計のみ。**

## カルテ機能のコンセプト

紙のテンプレートと同じ体験をデジタルで再現する:

1. 顔(将来的には手相・骨相・毛髪・行動データも)のイラストを見ながら、
   気になる部位をタップする
2. その部位に対応する `data/*.js` の項目(`role`)一覧が出てくるので、
   該当する選択肢(`options[].id`)を選ぶ
3. 選んだ内容が「その人のカルテ」に1件のエントリとして積み上がっていく
4. 加えて、紙のテンプレートの余白のような**自由記述メモ欄**も併設し、
   データベースにない気づきも記録できるようにする
5. 同じ人物について複数回(複数輯・複数回の面談)記録を重ねられるように、
   カルテは人物単位で日付ごとに複数エントリを持てる構造にする

## データモデル(提案)

既存の `PARTS`(`key`/`name`/`category`/`role`/`options[]`)配列は
**「相法の辞書」**であり、これ自体は変更しない。カルテは辞書を**参照**する
別のレイヤーとして設計する。

```js
// 1件のカルテ(=1人物についての鑑定記録の集合)
Karte = {
  id: string,              // uuid等の内部ID
  label: string,           // 表示名(実名でなくニックネーム/イニシャル推奨。下記プライバシー参照)
  createdAt: string,       // ISO日時
  updatedAt: string,       // ISO日時
  memo: string,            // カルテ全体に対する自由記述メモ(紙のテンプレートの余白に相当)
  entries: KarteEntry[],   // 蓄積される個別の観察記録
}

// 1件の観察記録(部位タップ→選択肢選択、または自由記述のみでもよい)
KarteEntry = {
  id: string,
  recordedAt: string,      // ISO日時(同じ人物でも日付をまたいで複数回記録できる)
  key: string | null,      // PARTS[].key への参照。自由記述のみの場合は null
  optionId: string | null, // PARTS[].options[].id への参照
  note: string,            // このエントリ固有の補足メモ(任意)
}
```

**重要:** `KarteEntry` は診断文そのものを複製せず、`key` + `optionId` の
参照のみを持つ。表示時に `PARTS.find(p => p.key === entry.key)` で辞書側の
最新の文言を都度引く。これにより、後日 `data/*.js` の文言を推敲・修正しても
過去のカルテ記録が自動的に最新の表現で表示される(辞書とカルテ記録を
二重管理しなくてよい)。

## 保存先とプライバシーの方針

- 実在の人物の顔の特徴を記録するデータなので、**サーバーへの送信・外部
  同期は行わない**。PWAとして完結させ、`localStorage` または
  `IndexedDB`(エントリ数が増える見込みなのでIndexedDB推奨)に
  端末内だけで保存する。
- `label` は実名でなく、イニシャルやニックネームでの記録を初期値の
  ガイドとして促す(placeholder等で軽く案内する程度でよい)。
- 将来的に写真を添付する機能を検討する場合も、画像は端末内保存に留め、
  この方針を継続する。
- エクスポート機能(カルテ単位でJSON/テキストとして書き出し)は将来
  検討してよいが、その場合も「本人の同意を得て記録・共有する」という
  一文をUI上に添えることを推奨する。

## UIの方向性(既存の `docs/UI_PROPOSAL.md` の手相タップ式マップと同じ思想)

### 1. 顔のタップ式マップ

`app/assets/palm-zones.svg` と対になる `app/assets/face-zones.svg` を
今回の土台として追加した(下記参照)。手相版との違いは:

- 手相の八卦ゾーンは1ゾーン=1項目(`data-key`+固定`data-option`)だが、
  顔の各部位は1ロールに複数〜十数十項目(例: 眼だけで55項目)ある。
  そのため顔ゾーンは `data-role`(例: `眼`, `鼻`, `眉`…)だけを持たせ、
  タップすると **そのroleに属するPARTS項目の一覧** が下に展開される
  二段階(またはロール選択→項目選択→選択肢選択の三段階)UIにする。
- 三段階目で選択肢(`options[].id`)を選んだ時点でカルテへの追加ボタンが
  出る、という流れを想定。

### 2. カルテ画面

- 「新しいカルテを作る」→ `label` を入力(実名でなくてもよい旨を案内)
- 顔マップ(将来的には手相・骨相・毛髪・行動のタブも)から部位を選び、
  該当する観察をどんどん追加していく
- 追加されたエントリは時系列リストとして表示し、後から削除・編集可能
- カルテ全体の自由記述メモ欄(紙のテンプレートの余白に相当)を用意
- カルテ一覧画面(複数人物を管理)も必要になる見込み

### 3. 既存の「単発鑑定モード」との関係

これまでの `PARTS` ブラウズ型UI(カテゴリ→ロール→項目を見るだけの
辞典的な使い方)は残しつつ、カルテ機能は「その場で選んだ項目を記録として
積み上げる」上位モードとして追加する形が自然(辞典モードで項目を見ながら
「カルテに追加」ボタンを出す、という統合も検討可)。
