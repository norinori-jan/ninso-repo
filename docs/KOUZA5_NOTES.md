# 人相講座5(全6回中5回目、5-1/5-2の2本、実演あり)動画からのノート

出典: 講座5-1・5-2の自動字幕(YouTube・日本語、実演あり)。これまでと
同様、個別受講者(実名)への具体的な鑑定内容は除外し、一般化できる技法
のみを抜き出している。方針も継続: **部位の定義は安易に書き換えず、
明確に「技法」と言える内容で、かつ座標や適用範囲に確信が持てるものだけ
を実装する。**

**今回の結論を先に書くと: コードの変更は行っていない。** 新しく出てきた
内容はどれも、(a)健康・生死に関わる断定的な判断(このアプリでは意図的に
実装しない方針)、(b)対話・問いかけを前提にした技法(1枚の画像を自動
解析する今のアプリの設計とは前提が異なる)、(c)座標が実物の図なしには
特定できない、のいずれかに該当したため。詳細は以下の通り。

## 1. 「小人形図」(顔の中に内臓の配置を重ねる技法) — 実装しない

顔の上に、小さな人の姿(頭・両腕・胴体)を重ねて、その各部位に内臓
(心臓・胃・腸・婦人科系など)を対応させ、その場所の色や線の状態から
健康状態を判断する、という具体的な技法が実演された(頬の高い位置=
心臓、その下=婦人科、など)。

**実装しない理由**: これは実質的に「顔色から特定の臓器・病気を判定する」
という、医学的診断に近い内容になる。このアプリは講座1・3のノートの
時点から一貫して「生死や病気に関する断定的な判定はしない」という方針を
とっており、今回もこの方針を維持する。座標も実物の図(講座で使われて
いた小人形の下敷き画像)がないと正確に再現できない。

## 2. 「妊娠線」「病院」の位置 — 実装しない(座標不明+機微な内容)

- 夫婦宮のあたりから伸びる、幅2〜3mm程度の白っぽい線が新しく現れたら
  妊娠のサイン、という技法が説明されていた。
- 「病院」という場所が独自にあり、そこに線が入ると入院・通院を表す、
  という説明もあった(講座2の「警察」と同種の、教科書の図に基づく
  独自ラベル)。

いずれも実装は見送る。妊娠のような個人的でデリケートな事柄を自動で
言い当てる機能は、外れた場合の影響が大きく、このアプリの「参考程度の
娯楽」という位置づけを超えてしまうと判断した。「病院」も座標が不明。

## 3. 「顔に問いかけて、答えとして像が浮かぶ」という技法 — 今のアプリの設計とは前提が異なる

講座5では、単に画像を眺めて何が見えるかを探すのではなく、**「この人は
今どうしているだろう」と心の中で問いかけながら見ると、その答えとして
具体的な画想(顔・場面など)が浮かんでくる**、という、対話的・意図的な
読み方が繰り返し強調されていた。「何もやってない人は出てこない」
「聞いたことについて出てくる」という発言から、これは受け手(占い師)側の
意図・集中がその都度必要な、対話的な技法であることが分かる。

→ 今のアプリは、1回の自動検出でその場に見えるものをすべて機械的に
マークする設計(講座1の「着眼点」の考え方の実装)であり、「何かを問い
かけて、その答えを待つ」という双方向のプロセスは再現できない。これは
設計思想の違いというより、**そもそもアプリの入出力モデルでは表現できない
種類の技法**なので、実装しないことを明記しておく。

## 4. 「画想」の実例が多数 — 既存機能の妥当性を改めて裏付け(コード変更なし)

「目があって、口があって、輪郭がこれくらいで顔になる」「複数の画想が
重なって(ダブって)見える」といった具体例が、講座2・4に続いて多数
出てきた。直前までに実装した「目・口のように並んだ構造(隠れた顔)を
点3つで示す」機能は、今回もその妥当性が裏付けられた形になる。複数の
画想が重なって見える(誰かの後ろに別の人物が透けて見える、等)という
話もあったが、これは今のアプリの「複数のF1・F2…を独立して検出する」
仕組みで、ある程度はすでに表現できていると考えている。

## 5. 流年法の続き(参考情報・引き続き未実装)

年齢の変化点を頬骨あたりから顎にかけて実演していたが、数字の書き起こし
精度はやはり十分ではなく(「20、25、28、30、33、35、40」のように
区切りらしきものは見えるが、正確な位置との対応が字幕だけでは追えない)、
これまでの回と同様、実装は見送る。
