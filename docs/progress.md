# 願相 自動検出(ヒューリスティック画像処理)実装セッション

## 今回やったこと

- ユーザーの要望「ラベル付き画像データなしでも点と線の組み合わせで顔に
  見える可能性の追求を実装したい」を受け、`app/hidden-face-detector.js`
  を新規実装。機械学習ではなく**古典的な画像処理**(閾値処理+連結成分
  ラベリング+幾何マッチング)による自動検出:
  - `detectDarkBlobs()`: 画像全体の平均輝度−標準偏差を閾値に、暗い画素の
    連結成分(フラッドフィル)を検出。ほくろ・瞳等の候補。サイズで
    ノイズ・巨大な影を除外。
  - `detectDarkRunInRegion()`: 指定範囲内で最も長い横方向の暗い画素の
    連なりを検出。しわ・口の候補。
  - `findFaceCandidates()`: 暗い塊のペア(目間隔・高さの妥当性で絞込み)
    +その下の線(口候補)の組み合わせを総当たりで探索し、
    `HiddenFaceEngine.computeFaceLikenessScore()`でスコア化、
    上位候補を返す。
  - **Node上で合成ピクセルデータ(Uint8ClampedArray)を使いユニット
    テスト実施**: 意図的に描いた「二点+線」パターンが正しく検出される
    (スコア88)こと、ノイズ画像・無地画像では高スコア候補が出ない
    ことを確認済み。
- `app/app.js`の画像マーキングモードに「自動検出する」ボタンを追加。
  アップロード画像を長辺240pxに縮小したオフスクリーンcanvasに描画→
  `getImageData()`→`findFaceCandidates()`→候補をスコア順にリスト表示→
  「採用する」で3点マーキングに自動反映(その後手動微調整も可能)。
- `app/index.html`・`app/service-worker.js`に
  `hidden-face-detector.js`の読み込みを追加。
- **jsdomでcanvasをスタブし、合成画像データを使った自動検出→採用→
  解析までのEnd-to-Endフローを確認済み**(候補1件・スコア88が正しく
  検出され、採用後の解析結果にも反映されることを確認)。テスト後、
  jsdomと`node_modules`/`package-lock.json`は削除済み。
- `docs/GANSOU_ROADMAP.md`を更新。検出層が「未着手」から「実装済み
  (ヒューリスティック版)」に変わったことを反映し、**ユーザー指摘の
  「ほくろ・しわを精緻に見るには精度が必要」という課題への具体的な
  次の一手**(局所適応閾値、肌色マスキング、平滑化、形状フィルタ、
  最終的なML化)を明記した。

## 今回持ち越し・今後の課題

- 精度向上策(局所適応閾値・肌色マスキング・平滑化・形状フィルタ)は
  いずれも未実装。`docs/GANSOU_ROADMAP.md`に具体案を記載済み。
- 実際のブラウザでの画像を使った自動検出の精度確認は未実施
  (jsdomでは合成データによるロジック検証のみ)。実機での実写真を使った
  確認を推奨。
- 検出パラメータ(閾値のk値、最小/最大面積、目の間隔の妥当範囲など)は
  暫定値のまま。実写真でのテスト結果を見ながら調整が必要になる見込み。
